> R-01 Reviewer note: BR2.6 fails an empty listing and a listing with no .safetensors file before any download. The empty or weightless repository has a business scenario, and the owner question is recorded under Decisions Taken.

> R-02 Reviewer note: BR5.5 closes the end game: a failed delete sets removalComplete to false and goes on, a failed email gives outcome removed-email-failed, the import always reaches done, and there is no removing to removing transition. The scanning to removing transition for a scan error is now in the lifecycle table. The new outcome value is recorded as an additive change to contract C4.

> R-03 Reviewer note: BR3.2 now gives the minimum length, the little-endian 8-byte read, the 100 million cap, UTF-8 JSON object, and bad-weight-header, and says the header text is deliberately not scanned. BR3.3 reads in 1 MiB parts and BR3.4 names the accepted encodings. AC3.1.2 and AC3.1.4 can be tested.

> R-04 Reviewer note: BR1.3 checks the model name, the version, and every file path before any write, fails duplicate and case-only duplicate paths, and lowercases the model name in the final location. A bad path fails through BR5.1.

> R-05 Reviewer note: BR5.6 writes the full list to the logs, lists the first 20 in the email in file path then place order, and adds an "N findings in total" line. entities.md says where ScanFinding records live.

> R-06 Reviewer note: BR4.1 now fixes the order (duplicate check, copy and note each object, then StoredModel and removal), names the keep failure, and refuses a final location that already holds the version. BR5.2 deletes the objects this import copied, so removalComplete is true only when nothing remains.

> R-07 Reviewer note: BR2.3 and BR2.4 now classify the answers, say a retry restarts the file, and treat a missing size as permanent. Remaining gap: the wait between retries is still left to NFR Design, and contract C2 still lists which server errors count as temporary as an open question that blocks u1. Record that the BR2.3 and BR2.4 lists answer it, or give the question an owner.

> R-08 Reviewer note: BR3.1 names the rule exactly (last segment, lowercase, text after the last dot, dotfiles with no ending), and the ignored-class risk is recorded under Decisions Taken as the owner's choice in Q2 and Q6.

> R-09 Reviewer note: BR3.7 caps recorded findings at 100 per file, BR3.3 reads in parts, and BR3.3 lists the smallest pattern set per kind. Remaining gap: nothing limits the total number of findings across many files or the total scan time (u1 has no time limit until u2), and the email, phone, and street-address patterns are described only as the "usual" form, so AC3.1.1 tests still rest on judgement. Give exact examples per kind, or name the stage that does.

> R-10 Reviewer note: BR1.1 now has an ELSE: nothing starts and one log line names the failed field without its value. The R-07 question about who may publish the event is recorded as an open question that passes to NFR Requirements and Infrastructure Design.

> R-11 Reviewer note: BR5.4 cleans file names (control characters replaced, 200 characters), the class moved to the new ScannedFile entity owned by LeakScanner, and BR5.2 includes incomplete uploads in the removal check.
