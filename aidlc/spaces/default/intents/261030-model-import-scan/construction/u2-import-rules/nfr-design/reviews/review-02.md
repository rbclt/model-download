> R-01 Reviewer note: reliability-design.md NFR4.14 now defines `KeepResult` (stored, marker_written, holding_emptied), `run.stored` in the coordinator, a rule that any exception after `run.stored` goes to `_finish` as stored and never to the removal, `_remove_and_notify` refusing a stored import, and a custodian set of marker-written imports that makes `remove` a no-op. The generic `except Exception` of `_keep` in coordinator.py is covered by item (3). The test list names an unexpected exception after the marker in each place part two can fail. A residual wrong-outcome path in the last guard is raised as a new Minor finding.

> R-02 Reviewer note: The removal now runs its final-location part only when the custodian's "writing" mark is set (after the pre-checks, before the first copy). `olderFilesRemoved` is the listing minus `_written`, and the source of this import's keys is named. A download or scan failure and a deadline stop before the keep step touch nothing and report 0. The test list includes a download failure and a pre-keep deadline stop with older files present. Reading the marker first and deleting it only when it holds this importId is consistent with BR9.2, which gives the same result for a foreign marker.

> R-03 Reviewer note: logical-components.md now has "Result of the First Parse" with the three results (`StartEvent`, `RejectedEvent`, `NotAStartEvent`) and what the worker does for each. `_process` takes the function to run, so the heartbeat, watchdog, stop signal and message deletion are shared. `has_outcome` runs on the importId for the rejected path, the log is bound with importId and eventId only, and worker.py and event.py are listed as changed. The correction of BR6.4 is recorded under "Decisions That Correct the Functional Design". It matches the worker as built, which logs `event_rejected` and deletes.

> R-04 Reviewer note: NFR4.17 now orders the checks: an S3 error other than not-found is a failed step (BR7.1), and only a fetched invalid body is refused. security-design.md "Settled Here" item 2 says the same, and the tests include a failing `HEAD` and a failing `GET`.

> R-05 Reviewer note: performance-design.md "Client Settings" designs a state client, a data client and a mail client, with the timeouts and attempt counts. It admits that u1 used SDK defaults, and the worker.py change is listed. A related gap in the custodian is raised as a new Minor finding.

> R-06 Reviewer note: The address `repr`, the optional `time`, the safe-pattern display of the eventId (acceptance stays as u1 built it, so nothing is narrowed), and the plain numeric duration fields (no `_aws` envelope, matching how coordinator.py writes `**seconds`) are now stated and listed as changes to event.py, worker.py and the coordinator.

### Suggestions

- NFR4.17 step (1) says "delete the message" when the outcome exists, but the coordinator cannot delete messages. The worker's `has_outcome` check owns this. Say so once to avoid a duplicate check.
- The log and record of a rejected event keep the raw eventId (up to 256 characters), while the email shows it only when it matches the safe pattern. Consider applying the same choice to the log field, so NFR3.19 holds for every sink.
- The `_COMPLETE` check "before any download, without case" is a change to the path checks (event.py or the downloader). Add it to the change list.
