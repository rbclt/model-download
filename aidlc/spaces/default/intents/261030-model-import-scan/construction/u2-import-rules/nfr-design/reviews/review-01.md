### Summary

The defects are in how three claims are built into the u1 code, not in the intent of the design. A stored model can still be destroyed by an unexpected error after the marker, the removal cannot count older files from a listing and does not say it waits for the keep step, and a bad-content start event cannot reach the coordinator because the worker still deletes it.

### Suggestions

- NFR3.25 and NFR4.19 are settled: the `_COMPLETE` check before download, the refusal of an unreadable marker, and the Unexpected Stop section state the consequences plainly. The only gap is the transient-error case above.
- BR6.4 is changed (not-a-start-event messages are logged and deleted, no alert) and recorded only as an open question in logical-components.md. Say in security-design.md or logical-components.md that this replaces the sentence in BR6.4, so the Functional Design record matches.
- The 10-minute claim holds only if every longest uninterrupted piece is bounded: the 5-minute scan limit is stated for text files, so confirm that scanning a large binary file is also bounded or checked per chunk. The check per chunk inside `hf_client.py` and the handling of `DeadlineReached` inside retry loops could not be verified here (those files were out of the review's scope). The copy time of 5 GiB is stated as an assumption.
- The removal deletes the marker whenever a marker write was attempted. Reading the marker first and deleting it only when it holds this import's importId would be safer and cost one request.
